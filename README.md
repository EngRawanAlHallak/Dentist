## 📌 نبذة عن المشروع (Overview)

نظام رقمي متكامل يجمع **طلاب طب الأسنان والمرضى والمشرفين والأطباء والإداريين** في بيئة واحدة لتنظيم التدريب السريري العملي في الجامعة. يعالج المشروع مشكلات حقيقية في التدريب التقليدي: عدم تكافؤ فرص الحصول على مرضى، وتسلّم حالات غير مناسبة سريرياً، واستغلال قسم الأشعة، وضعف تتبع الأداء والإشراف.

يخدم النظام تطبيقات **Flutter** (الطالب، المريض، المعيد) وبوابات **React** (الإدارة، القبول، الأشعة) عبر **واجهة خلفية مركزية (RESTful API)** مبنية بـ Laravel، وهي موضوع هذا المستودع.

| :--- | :--- |
| **نوع المشروع** | مشروع السنة الرابعة — قسم هندسة البرمجيات |
| **الجامعة** | جامعة دمشق — كلية الهندسة المعلوماتية |
| **تاريخ التسليم** | أيلول / سبتمبر 2025 |
| **دوري في المشروع** | مطورة Backend (Laravel) |

## 🎯 أهداف المشروع (Key Objectives)

* **عدالة توزيع المرضى**: إظهار الطلاب كأطباء متاحين بالتساوي للمرضى، وإزالة الطالب مؤقتاً من القائمة بعد أخذ حالة حتى تتساوى أعداد الحالات بين جميع الطلاب.
* **توجيه الحالات سريرياً**: مكتب قبول افتراضي يراجع بيانات المريض وصور الأشعة ويوجّهه للتدريب المناسب.
* **منع استغلال قسم الأشعة**: رفع صور الأشعة مباشرة للنظام، وربط الحصول عليها بتسجيل حالة علاجية فعلية.
* **رفع الوعي الطبي للمرضى**: تسجيل الأمراض المزمنة وصور الأدوية ليحصل الطبيب على معلومات دقيقة.
* **توثيق التدريب والتقييم**: أرشيف رقمي للجلسات السريرية وتقييم ومتابعة أداء الطالب.

## 🏗️ بنية النظام (Architecture)

```
  Flutter Apps (Student / Patient / Supervisor)     React Portals (Admin / Admissions / Radiology)
                          │                                        │
                          └──────────────►  REST API  ◄────────────┘
                                              │
                        Controllers  →  Services  →  Eloquent Models  →  MySQL
                        (MVC)           (Business Logic)               (ACID, Indexed)
```

* بنية **MVC** مع **طبقة Services** تتولى العمليات المعقدة: توزيع المرضى، تسجيل الحالات السريرية، معالجة التقييمات.
* **MySQL** لدعم معايير **ACID**، مع **Indexes** على الجداول الأكثر استعلاماً وتصميم يتجنب الـ Anti-Patterns.

## ✅ ما تم تنفيذه (Implemented Features)

### 1. الحسابات والصلاحيات (سبعة أدوار)
* الأدوار: **طالب، مريض، معيد (مشرف عملي)، دكتور، مسؤول قبول، مسؤول أشعة، مدير النظام**.
* تسجيل الدخول: بالرقم الوطني لكوادر الكلية، وبرقم الهاتف للمريض.
* **تسجيل المريض والتحقق عبر SMS OTP**، واستعادة كلمة السر بـ OTP لجميع الأدوار.
* **صلاحيات وصول** مخصصة لكل دور (Role-Based Access Control).

### 2. توزيع المرضى وسير الطلب العلاجي
* **خوارزمية التوزيع العادل** للحالات بين الطلاب.
* دورة حياة طلب المريض: رفع الأشعة ← إنشاء طلب معالجة وإعلام القبول ← فرز الطلب للتدريب المناسب (`Processed`) ← إشعار المريض ليختار الطالب.
* توزيع الطلاب على حصص التدريب والفئات بشكل تلقائي.

### 3. المواعيد والجلسات العلاجية
* الطالب يضيف ويعدّل أيامه ومواعيده المتاحة.
* المريض يحجز موعداً مع طالب (يوم + ساعة) بعد **التحقق من التوفر**، مع إشعار الطالب.
* توثيق الجلسة: صور قبل وبعد العلاج ووصف الحالة، وأرشيف الجلسات عبر السنوات.

### 4. التقييم والمتابعة
* الطالب يولّد **QR Code** للجلسة المطلوب تقييمها، والمعيد أو الدكتور يمسحه ليعرض الجلسة ويقيّمها ويضيف تعليقاً.
* حساب متوسط علامات الطالب، وتسجيل الحضور والغياب وتنزيل تقرير الحضور.
* تنزيل أرشيف الطالب كـ **Portfolio بصيغة PDF**.

### 5. قسم الأشعة والقبول والإدارة
* رفع صور المريض (`jpg/png`) بنوع `x-ray` أو `real-image`، وإنشاء حساب مريض من قسم الأشعة.
* إحصائيات أسبوعية لكل تدريب (عدد الجلسات ومتوسط التقييمات) ولوحة إحصائيات للأشعة والإدارة.
* إدارة المستخدمين وجداول العملي والتدريبات المقررة.

### 6. خدمات إضافية
* **نظام إشعارات** (عرض / قراءة / حذف)، ودعم وشكاوى عبر البريد الإلكتروني.
* محتوى تعليمي (فيديو، مقال، محاضرات) وقسم تبادل الأغراض بين الطلاب.

## 🔐 الأمان (Security)

* التحقق بـ **OTP** عبر SMS لتأكيد صاحب الحساب.
* **صلاحيات وصول** حسب نوع المستخدم، وعزل بيانات كل دور.
* بروتوكول **SSL/TLS** لحماية بيانات المرضى والطلاب، والالتزام بمعايير الخصوصية الطبية.
